# 折纸渲染数据结构设计记录

项目仓库： [Gui-Yun/Cognito](https://github.com/Gui-Yun/Cognito.git)

## 1. 目标与任务背景

希望设计一个折纸仿真程序，支持以下基本操作：

1. 从一张初始纸张开始；
2. 沿指定折痕进行折叠；
3. 支持连续折叠 2–3 次；
4. 能够对折叠后的局部区域进行剪切；
5. 剪切完成后可以展开，得到最终纸张形状。

这个任务表面上是二维几何变换问题，但实际上涉及三个层面的状态管理：

- 原始纸面上每一块区域的位置；
- 当前折叠状态下每一块区域的显示位置；
- 多层纸之间的重叠与上下层关系。

因此，它不仅是“线段折叠公式”的问题，更是一个关于材料区域、几何映射和层级关系共同维护的问题。

---

## 2. 初始想法

最初的设计思路偏向几何对象封装，核心想法包括：

### 2.1 线段封装

将纸张边界、折痕、剪切边界等都抽象为线段。

线段可以用两个端点表示：

```python
class Segment:
    p1: Point
    p2: Point
```

考虑到折纸中会大量出现平行、垂直、相交、反射等几何关系，用两个端点来表示线段是比较自然的。

### 2.2 区块封装

将纸面划分成若干区块，每个区块由若干线段围成，并可能带有正负号。

其中正负号初步用于表示区块相对于折痕的位置，例如位于折痕一侧为正，另一侧为负。

### 2.3 形状封装

将完整形状表示为若干依次相连的区块或线段集合。

初步设想中，一个形状满足：

- 线段首尾相接；
- 边界形成闭合区域；
- 区块之间的符号关系满足某种规律；
- 折叠后通过更新线段位置和区块符号来表示新形状。

### 2.4 操作队列

通过操作队列记录折叠和剪切历史：

```python
operations = [
    FoldOperation(...),
    FoldOperation(...),
    CutOperation(...),
    UnfoldOperation(...)
]
```

理想情况下，可以通过依次执行操作来得到当前形状，也可以通过逆向操作来展开。

### 2.5 折叠函数

初步设想是为折叠定义一个几何函数：

```python
def fold(shape, crease_line, side):
    ...
```

对于一张未折叠的纸，这个函数可以相对简单地实现：

1. 判断纸张哪一部分位于折痕一侧；
2. 将这一侧沿折痕进行反射；
3. 得到折叠后的形状。

## 3. 初始设计的优点

初始方案有几个明显优点。

### 3.1 几何上简洁

线段、折痕、区块、形状都是直观的几何对象。对于单次折叠来说，整体逻辑比较自然：

```text
shape → fold(shape) → new_shape
```

折叠可以被理解为对某一侧几何区域做反射变换。

### 3.2 操作表达清晰

用操作队列记录折叠和剪切，可以清楚描述用户的操作历史。这个思路对于撤销、重做、动画回放都有潜在价值。

### 3.3 适合简单折叠

如果只处理一张纸的一次折叠，不涉及多层重叠，也不涉及复杂剪切，那么这种几何驱动的设计是可行的。

---

## 4. 初始设计的核心问题

虽然初始设计在几何上比较简洁，但它隐含了一个危险假设：

```text
当前几何对象 ≈ 纸的真实状态
```

这个假设在第一次折叠时基本成立，但在多次折叠、剪切和展开之后会失效。

### 4.1 当前轮廓不等于纸本身

折叠后的可见形状只是多层纸在当前视角下的投影。一个可见区域下面可能叠着多块来自原始纸面不同位置的区域。

因此，不能只用当前外轮廓来表示整张纸。

例如，折叠后看到的一个矩形区域，可能实际上由三层纸组成：

```text
当前可见区域 A
├── 原始纸面左上区域
├── 原始纸面右侧区域
└── 原始纸面下方区域
```

如果只记录当前轮廓，就无法知道这些层分别来自原纸的哪里。

### 4.2 多次折叠会导致状态混乱

第一次折叠时，可以简单地将一侧区域反射过去。但第二次折叠时，折痕可能穿过已经重叠在一起的多层纸。

此时需要判断：

- 哪些原始面片被当前折痕切过；
- 哪些面片位于折痕的一侧；
- 哪些面片属于这次被一起翻折的纸层；
- 翻折后这些面片的上下层关系如何变化。

如果只维护一个当前 shape，这些信息会丢失。

### 4.3 区块的正负号不是固定属性

初始设计中希望为区块设置正负号，但这个正负号只在相对于某一条折痕时才有意义。

同一个区块相对于折痕 A 可能是正侧，相对于折痕 B 可能是负侧。因此，正负号不应该作为区块的永久属性，而应该在每次折叠时临时计算。

更合理的方式是：

```python
side = classify_polygon_side(face_current_polygon, crease_line)
```

### 4.4 剪切必须穿透多层

折叠后剪切一个区域，剪刀并不是只剪掉当前最上层的可见轮廓，而是可能穿透所有重叠在该区域内的纸层。

因此，需要知道当前剪切区域覆盖了哪些原始面片，并把剪切结果映射回原始纸面。

如果只记录当前折叠后的 shape，就很难在展开时判断原始纸面上到底哪些区域被剪掉了。

### 4.5 展开不应该依赖反向折叠硬算

如果系统只记录 folded shape，那么展开时就需要倒放所有折叠操作，并处理剪切导致的拓扑变化。

这会非常复杂，而且容易出错。

更稳定的设计应该让每个纸面区域始终知道自己来自原始纸面的哪一块。这样展开时只需要回到原始坐标系显示剩余区域，而不是逆向模拟所有折叠。

---

## 5. 问题本质总结

初始设计的问题不是线段、折痕或反射公式本身有问题，而是系统状态建模的层级不够。

原设计偏向：

```text
几何驱动：
shape → fold(shape) → cut(shape) → unfold(shape)
```

但折纸剪切任务更适合：

```text
材料驱动：
paper_material_faces + current_pose
→ fold/update_pose
→ cut/update_material
→ unfold/show_material
```

关键区别是：

- 原设计把“当前看到的几何形状”当作纸本身；
- 改进方案把“原始纸面区域”和“当前折叠显示状态”分离。

一句话总结：

```text
折纸仿真不能只建模几何形状，还必须建模“这块几何来自哪一块纸”。
```

## 6. 改进方案：基于面片的材料—姿态双层结构

更稳妥的方案是将纸张表示为一组面片。每个面片同时保存：

1. 它在原始纸面上的区域；
2. 它在当前折叠状态中的几何变换；
3. 它当前的层级顺序；
4. 它是否还存在。

核心结构可以是：

```python
class Face:
    id: int
    material_polygon: Polygon      # 原始纸面坐标系中的区域
    transform: Matrix3x3           # 从原始坐标映射到当前折叠坐标
    layer_order: int               # 当前层级顺序
    alive: bool                    # 是否被剪掉
```

整张纸表示为：

```python
class Paper:
    faces: list[Face]
    creases: list[Crease]
    operations: list[Operation]
```

这个方案的核心是同时维护两个坐标系。

### 6.1 Material space：原始纸面坐标系

`material space` 表示纸张未折叠时的原始坐标。

每个面片都有自己的 `material_polygon`，它记录这块纸真实来自原始纸面的哪一块。

### 6.2 Folded space：当前折叠坐标系

`folded space` 表示当前折叠后用户看到的坐标。

每个面片通过自己的 `transform` 从原始坐标映射到当前坐标：

```text
folded_point = transform × material_point
```

折叠操作主要更新 `transform`；剪切操作主要更新 `material_polygon`。

---

## 7. 折叠操作设计

一次折叠可以拆成以下步骤：

```text
1. 用折痕切分被穿过的面片；
2. 判断每个面片在当前 folded space 中位于折痕哪一侧；
3. 选择需要被翻折的一侧；
4. 对这一侧面片施加沿折痕的反射变换；
5. 更新层级关系。
```

伪代码：

```python
def fold(paper, crease_line, side_to_fold):
    # 1. 切分所有被折痕穿过的面片
    paper.faces = split_faces_by_line(paper.faces, crease_line)

    moving_faces = []
    fixed_faces = []

    # 2. 判断面片位于折痕哪一侧
    for face in paper.faces:
        folded_poly = apply_transform(face.transform, face.material_polygon)
        side = classify_polygon_side(folded_poly, crease_line)

        if side == side_to_fold:
            moving_faces.append(face)
        else:
            fixed_faces.append(face)

    # 3. 构造沿折痕反射的矩阵
    R = reflection_matrix(crease_line)

    # 4. 更新被折过去面片的 transform
    for face in moving_faces:
        face.transform = R @ face.transform

    # 5. 更新上下层级
    update_layer_order(moving_faces, fixed_faces)
```

这种方式下，多次折叠不会破坏原始材料信息。每个面片始终知道自己来自原始纸面的哪个区域。

## 8. 剪切操作设计

剪切操作应该在当前折叠状态中定义，但结果要作用回原始纸面。

流程如下：

```text
1. 用户在 folded space 中指定剪切区域；
2. 判断该区域与哪些当前面片相交；
3. 对每个被命中的面片，将剪切区域通过 transform 的逆变换映射回 material space；
4. 在 material space 中对 face.material_polygon 做 difference；
5. 如果面片面积接近 0，则标记为删除。
```

伪代码：

```python
def cut(paper, cut_polygon_folded):
    for face in paper.faces:
        if not face.alive:
            continue

        folded_poly = apply_transform(face.transform, face.material_polygon)

        if intersects(folded_poly, cut_polygon_folded):
            invT = inverse(face.transform)
            cut_polygon_material = apply_transform(invT, cut_polygon_folded)

            face.material_polygon = difference(
                face.material_polygon,
                cut_polygon_material
            )

            if area(face.material_polygon) < EPS:
                face.alive = False
```

这个设计能自然处理“剪刀穿透多层”的问题。因为所有与剪切区域相交的面片都会被分别映射回原始坐标并裁剪。

## 9. 展开操作设计

展开不需要逆向执行所有折叠操作。

只要系统一直保存每个面片的 `material_polygon`，展开时直接显示所有仍然存在的原始面片即可：

```python
def unfold(paper):
    return [face.material_polygon for face in paper.faces if face.alive]
```

也就是说：

```text
展开 = 回到 material space 显示剩余纸面
```

这比倒放折叠历史稳定得多。

---

## 10. 层级关系的处理

严格的折纸层级关系会非常复杂，但对于 2–3 次折叠和剪切仿真，可以先采用简化方案。

每个面片维护一个整数层级：

```python
face.layer_order: int
```

折叠一叠纸时，可以简单将被翻折的面片移动到另一组面片之上或之下。

需要注意的是，整叠纸翻转后，其内部层级顺序通常会反转：

```text
翻折前：
上层 A
中层 B
下层 C

翻折后：
上层 C
中层 B
下层 A
```

可以先使用近似规则：

```python
def flip_layer_order(moving_faces):
    orders = sorted([f.layer_order for f in moving_faces])
    reversed_orders = list(reversed(orders))

    for face, new_order in zip(
        sorted(moving_faces, key=lambda f: f.layer_order),
        reversed_orders
    ):
        face.layer_order = new_order
```

如果剪切默认穿透所有重叠层，那么层级主要用于显示，而不是决定剪切是否生效。

## 11. 初始方案与改进方案对比

| 方面     | 初始方案            | 改进方案                               |
| -------- | ------------------- | -------------------------------------- |
| 核心对象 | 线段、区块、形状    | 面片 Face                              |
| 状态表示 | 当前几何轮廓        | 原始面片 + 当前变换                    |
| 折叠逻辑 | 对 shape 做反射     | 切分 face，更新 transform              |
| 剪切逻辑 | 在当前 shape 上裁剪 | folded space 命中，material space 裁剪 |
| 展开逻辑 | 可能需要逆向操作    | 直接显示 material_polygon              |
| 多层重叠 | 难以表达            | 通过 face + layer 表达                 |
| 多次折叠 | 容易失控            | 状态相对稳定                           |
| 正负号   | 作为区块属性        | 每次相对折痕临时计算                   |
| 操作队列 | 用于驱动状态        | 用于历史记录、撤销、回放               |

## 12. 推荐的最小可行版本

为了避免一开始设计过重，可以先实现一个最小版本。

### 12.1 基础类

```python
class Point:
    x: float
    y: float

class Polygon:
    vertices: list[Point]

class Face:
    id: int
    material_polygon: Polygon
    transform: Matrix3x3
    layer_order: int
    alive: bool

class Paper:
    faces: list[Face]
    operations: list[Operation]
```

### 12.2 必要几何函数

```python
split_faces_by_line(faces, line)
classify_polygon_side(polygon, line)
reflection_matrix(line)
apply_transform(transform, polygon)
inverse(transform)
intersects(poly1, poly2)
difference(poly1, poly2)
```

### 12.3 必要操作

```python
fold(paper, crease_line, side_to_fold)
cut(paper, cut_polygon_folded)
unfold(paper)
```

### 12.4 可选工具库

如果用 Python，可以考虑：

- `shapely`：多边形切分、相交、差集；
- `numpy`：矩阵变换；
- `matplotlib` 或其他前端可视化工具：显示 folded space 和 material space。

## 13. 最终设计原则

这个折纸仿真程序最重要的设计原则是：

```text
不要把当前看到的轮廓当成纸本身。
```

更稳的抽象是：

```text
Paper = 一组 Face
Face = material_polygon + transform + layer_order + alive
```

其中：

- 折叠主要改变 `transform` 和 `layer_order`；
- 折痕可能导致 `Face` 被切分；
- 剪切主要改变 `material_polygon`；
- 展开直接显示剩余的 `material_polygon`。

最终总结：

```text
初始方案在几何上简洁，但把当前形状当作全局状态，导致多次折叠、剪切和展开后容易失控。

改进方案将“原始纸面材料”和“当前折叠姿态”分离，用面片作为核心状态单位，使多次折叠、穿透剪切和展开都变得可控。
```
